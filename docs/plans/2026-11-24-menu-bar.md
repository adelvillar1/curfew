# Plan — the menu bar (L5.2)

## Context

The TUI is a screen you have to open. Quiet mode is a state you should be able to see and undo from
wherever you are. This atom is a status item: one glyph, a menu, and the two things worth doing from
it — see the state, and put the machine back.

**It never applies (D23).** `apply --execute` stays a deliberate CLI act. Restore is offered because
restore is the direction that returns the machine to how you left it.

## Approach

Same split as the TUI, for the same reason:

- `MenuBarModel` — sections, items, titles, enabled states. Pure and tested (6 tests).
- `curfew-menubar` — AppKit: one `NSStatusItem`, a menu built from the model, three actions (restore,
  open dashboard, quit). `@MainActor`, because AppKit is.
- `make app` — bundles it as `Curfew.app` with `LSUIElement`, ad-hoc signed. No Developer ID: nothing
  is distributed (D21).

The glyph carries the state: `○` when quiet mode is off, `◐ N` when it is on and holding N intents.

`--dump-menu` prints the same model without touching AppKit, which is the only part a session without
a screen can check.

## Acceptance criteria

- [x] `curfew-menubar --dump-menu` prints the menu for both states and exits 0.
- [x] The glyph is `○` off and `◐ N` on (tested).
- [x] Restore is disabled and reads "Nothing to restore" when the journal is clean; enabled otherwise.
- [x] Informational rows are never clickable; dashboard and quit always are.
- [x] `make app` produces a signed `Curfew.app` that launches and stays running.
- [ ] **Visual confirmation that the status item appears** — unverified from this session: screen
      capture is denied (`could not create image from display`) and System Events needs Accessibility.
      `lsappinfo` confirms the app registers as "Curfew" and the process stays alive.

## Out of scope

Applying from the menu bar, a settings window, notifications, and login-item registration.
