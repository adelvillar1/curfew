# Plan — the TUI (L5.1)

## Context

Every command works and none of them is a screen. `curfew list` is a wall of text; deciding what to
quiet means reading it. This atom is the first face: one screen that says what is running, what is in
the bundle, and whether quiet mode is on.

**It previews and never acts.** `apply --execute` stays a CLI act with `--yes`. A TUI whose `a` key
stops a database is a TUI that stops a database on a typo.

## Approach

Split three ways so the screen is testable without a terminal:

- `TUIState` — rows, cursor, bundle selection, message. Pure.
- `TUIRenderer` — state → text, at a given width. Pure, so "the quiet-mode banner is always visible"
  is a test.
- `TUILoop` — raw mode, read a key, redraw. Only moves bytes.

Shape of the screen:

```
curfew 0.1.0 · macOS 26.5.2 · gui/501                              quiet mode: off
──────────────────────────────────────────────────────────────────────────────────
  SERVICES        FINDINGS
▸ [ ] com.adelvillar1.blend1-service           running
  [·] com.adelvillar1.sem1-llama               running
  [ ] com.docker.helper                        notLoaded   1 finding(s)
  … 15 more
──────────────────────────────────────────────────────────────────────────────────
bundle: harness-core   selected: 0   in bundle: 2   hidden: 18 (protected + app-bound)
──────────────────────────────────────────────────────────────────────────────────
j/k move · space select · b next bundle · a preview (dry run) · r refresh · q quit
read-only: this screen previews; only `curfew apply --execute` changes anything
```

Three choices worth stating:

1. **`application.*` rows are excluded** (D0): they are running GUI instances, not services anyone
   manages. Protected-tier jobs are excluded too — they can never be actioned — and both are *counted*
   in the footer so the screen does not pretend they do not exist.
2. **`quiet mode: ON` is on the header of every frame**, with the reason. A mode that suspends services
   must never be invisible (functional spec §6).
3. **`--frame` prints one screen and exits**, and a non-TTY stdin does the same automatically. That is
   how this atom is verified from a script, and it keeps the screen usable in a pipe.

## Acceptance criteria

- [x] `curfew tui --frame` renders against live data and exits 0.
- [x] `curfew` with no arguments opens the TUI; a non-TTY gets one frame.
- [x] The header carries `quiet mode: off` when the journal is clean and `QUIET MODE: ON` when it holds
      an unresolved intent (verified against a hand-written journal).
- [x] App-bound and protected rows are excluded; the hidden count appears in the footer.
- [x] Navigation clamps at both ends; `space` toggles; `b` cycles bundles and re-marks membership.
- [x] The cursor stays visible: the window scrolls once the list exceeds the height budget.
- [x] Arrow keys (`ESC [ A` / `ESC [ B`) and `j`/`k` both move; a bare `ESC` quits.
- [x] Nothing in the TUI writes to the journal or runs a recipe — the loop has no runner.
