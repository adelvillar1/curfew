# Curfew 0.2.1

Your Mac has been partying hard, fast and loose — essentially an unruly teenager. This is the version that
turns the lights on.

**Download:** `Curfew-0.2.1.dmg` below · Apple silicon · macOS 13 or newer.

## Read this before you open it

The disk image is **ad-hoc signed and not notarised** — there is no Developer ID on the machine it was built
on, and notarisation needs a paid Apple account. macOS will therefore refuse it on first open with
*"cannot be opened because the developer cannot be verified"*. Two ways through, both standard:

```
# option 1: right-click the app in /Applications → Open → Open
# option 2: clear the quarantine bit once
xattr -dr com.apple.quarantine /Applications/Curfew.app
```

Same for the bundle inside: drag `Curfew.app` onto the `Applications` shortcut in the window.

## What it is

A macOS tool that puts the machine into a quiet, unattended-development state — stopping the vendor updaters,
launchers and sync agents a build does not need — and then puts every one of them back, the way it found it,
when you ask. Every stop is a plan first, written to a journal before it happens.

## What is new in 0.2.1

- **The app has an icon.** 0.2.0 shipped with the stock macOS placeholder; the bundle now carries the
  crescent-and-power mark as `AppIcon.icns`, sealed inside the signature.
- The README explains both ways in: the installer, and a from-source build with no dependencies.

## What is new since 0.1.0

- **The window.** A five-pane app: Quiet mode, Bundles, Findings, Services, Apps — with a keyboard path
  (⌘⇧Q start, ⌘⇧Z restore, ⌘1–⌘5 panes, ⌘F filter, ⌘? help).
- **Rows speak English.** `application.com.apple.ActivityMonitor.1152…1908417` reads as *Activity Monitor*,
  with the launchd label kept underneath for the CLI.
- **The Apps pane.** GUI apps by memory — they hold ~2.4–4 GB where the daemons hold ~20 MB — with freeze as
  the reversible default.
- **Hygiene.** Orphaned keep-alives named (and reapable, after a confirmation), build artifacts listed with
  what a live run would prune, and a reclaim action that deletes only what both guards allow.
- **Quarantine.** Debris from a removed app is moved, never deleted, and only when the owner is verifiably gone.
- **A session close** that stops what the run spawned and never deletes a record.

## What it does not do

- **It will not run on Intel.** This build is arm64 only.
- **It does not update itself.** No Sparkle, no appcast; a new release is a new download.
- **The mutating half is young.** Refuse → journal → act → verify → journal is proven by tests and by a
  crash-recovery script, and it has run against the machine it was built on. It has not been used broadly.
